## 1. Fix the pending-form auto-approval bug

The original business workflow requires Operations to approve a teacher renewal form before a booking request can proceed.

Current bug:
- `FORM_PENDING` is currently informational.
- `_auto_gates_pass()` does not explicitly require `approval_status == Approved`.
- The synthetic test currently expects a Pending form to become AUTO_APPROVED when other evidence gates pass.

Required behavior:
- A form with `approval_status=Pending` must never result in `AUTO_APPROVED`.
- Add an explicit approval-status gate inside `_auto_gates_pass()`.
- Require exactly one linked form and require its normalized approval status to equal `Approved`.
- Missing, blank, unknown, rejected, or pending approval status must fail the auto-approval gate.
- Keep `FORM_PENDING` visible as a finding. Use a severity that clearly requires Operations action, not informational-only.
- Add appropriate handling for rejected or unknown statuses if not already present. Do not invent business transitions.
- Do not automatically change a form's status or create a booking request.
- Preserve `auto_approval_enabled=false` in the default policy.

Important distinction:
`AUTO_APPROVED` in this prototype means the renewal eligibility decision passed configured checks. It does not mean a booking request or class schedule was created. Document this distinction clearly.
